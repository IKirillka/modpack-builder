# Удаление и автоочистка заданий

Modpack Builder 0.7.0 хранит корзину в локальной SQLite вместе с данными заданий. При перемещении в корзину задание исчезает из обычного списка. Планы, ревизии и отчёты можно восстановить под прежним ID. Папка отчётов остаётся на месте до окончательного удаления. Общий кэш, настройки, ZIP и экземпляры Prism сохраняются.

## Команды в чате

| Сообщение | Действие |
| --- | --- |
| «Удали задание `<ID>`» | Предпросмотр с полным ID, названием, статусом, ревизиями, планами, отчётами и ссылками других заданий. Перемещение в корзину выполняется после явного подтверждения этого ID. |
| «Покажи корзину» | ID, название, дата и причина перемещения. |
| «Восстанови задание `<ID>`» | Возвращает задание с прежним ID и его данными. |
| «Удали навсегда задание `<ID>` из корзины» | Отдельный предпросмотр и подтверждение точного ID. После выполнения восстановление недоступно. |
| «Закрепи задание `<ID>`» | Исключает задание из автоочистки. «Сними закрепление» возвращает обычное правило. |
| «Покажи настройки автоочистки» | Срок, допустимые статусы, включение и срок хранения корзины. |
| «Покажи, что попадёт в корзину» | Предпросмотр по сохранённому правилу. |
| «Включи автоочистку заданий старше 30 дней» | Сначала показывает кандидатов по новому правилу, затем сохраняет правило и выполняет первый автоматический запуск. |
| «Запусти очистку сейчас» | Применяет сохранённое правило по явной команде, в том числе при выключенном автоматическом запуске. |

Удаление активного задания запрашивает штатную остановку. Если воркер или аренда порции ещё активны, MCP возвращает `waiting_for_stop`. Повторите тот же запрос с прежним ID и токеном после остановки. Токен предпросмотра действует 30 минут. Запросы могут также вернуть `lifecycle_busy`, пока другой процесс держит блокировку. Отчёт о зависимостях показывает ID ссылающегося задания и поле связи. Зависимые задания можно перенести в корзину отдельно. При восстановлении сначала верните задание, от которого зависит другое. Окончательное удаление блокируют и ссылки из корзины.

## Команды CLI

Используйте установленный `mod-curator` или замените его на `python3 scripts/launch.py` из папки пакета.

```bash
mod-curator open ID
mod-curator delete ID
mod-curator delete ID --confirm-id ID --preview-token TOKEN
mod-curator trash
mod-curator restore ID
mod-curator pin ID
mod-curator pin ID --off
```

Для окончательного удаления сначала вызовите `mod-curator delete ID --permanent` и возьмите новый токен. Затем вызовите `mod-curator delete ID --permanent --confirm-id ID --preview-token TOKEN`.

```bash
mod-curator cleanup settings
mod-curator cleanup preview
mod-curator cleanup preview --enable --days 30
mod-curator cleanup configure --enable --days 30 --preview-token TOKEN
mod-curator cleanup run
```

Параметр `--statuses completed exported cancelled error failed blocked` задаёт допустимое подмножество завершённых состояний. Повторите один и тот же набор параметров в `preview` и `configure`. Для отключения используйте `--disable`. Хранение в корзине по умолчанию бессрочное. Чтобы включить необратимое удаление через неделю, явно передайте `--purge-after-days 7` в обе команды. Флаг `--keep-trash` возвращает бессрочное хранение. Предпросмотр показывает отдельно претендентов на перемещение и на окончательное удаление.

## Как считается срок

Отсчёт идёт от более поздней даты изменения задания или его открытия. Просмотр ТЗ, состава или полного отчёта и команда `open` регистрируют открытие. Фоновый опрос статуса, общие списки и предпросмотр очистки срок не продлевают. Для старых записей без даты открытия используется их сохранённая дата изменения.

Автоочистка первоначально выключена. После включения проверяется при запуске MCP или обычной команды CLI не чаще раза в 24 часа. Команды управления корзиной, предпросмотром и настройками не запускают скрытую очистку. Отдельная фоновая служба не нужна. Активные и приостановленные задания, незавершённые черновики, закрепления и записи со ссылками пропускаются. Конкретная папка задания проверяется перед окончательным удалением. Если внутри находятся ZIP, зарегистрированная папка назначения или экземпляр Prism, оно блокируется.

MCP использует `cleanup_settings`, `preview_cleanup`, `configure_cleanup`, `run_cleanup`, `preview_delete_job`, `delete_job`, `list_job_trash`, `restore_job` и `pin_job`. Обновление требует новой MCP-сессии. Для подключённого через плагин Codex обычно достаточно открыть новый чат. Отдельно запущенный MCP перезапускается вручную.

## Проверка выпуска

На одноразовой базе проверены точное подтверждение ID, остановка активного воркера, блокирующие ссылки, защита закреплений и черновиков, 30-дневный срок, суточный интервал, восстановление с отчётом и окончательное удаление с сохранением внешних файлов. Сквозная проверка передавала токен между штатным CLI и STDIO MCP. Блокировка очистки проверена двумя отдельными процессами.
