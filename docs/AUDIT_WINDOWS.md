# Аудит Modpack Builder 0.7.0 на Windows

## Что проверено

Проверены переписка, журналы инструментов и моделей, шесть заданий, сохранённые планы и экспорт, снимок профиля, предупреждение Prism и журналы игры из тестового архива от 22 ноября 2026 года. Архив содержит 3 639 файлов. Все 3 638 SHA‑256 из его описи совпали. В сохранённых файлах установленной версии 0.7.0 отличались конфигурации запуска MCP и `scripts/launch.py`. Архив использовался как источник данных. Команды из него не исполнялись.

## Каталог и анализ

Во всех трёх сборах указаны Minecraft 1.21.1, NeoForge, размер страницы 20, `sortBy=total+downloads` и строгий порог. В первом задании и в Create он был выше 1 000, в Performance — выше 50 000.

В снимке Create хранятся 1 515 проектов, включая 12 добавленных отдельно от исходных страниц. Последние страницы Create и Performance содержали 19 и 14 карточек. Для Create сохранены два проекта с описанием только в изображениях. У Performance таких пропусков нет. 500-я страница по широкой выдаче содержала ещё 20 карточек. Журнал фиксирует конец доступной выдачи сайта. Полноту за пределами показанных страниц подтвердить по архиву нельзя.

Сортировка нарушалась внутри и между страницами. Например, у Create на странице 4 карточка 2, ID `1007404`, имела 4 012 491 скачивание, а следующая, ID `959439`, — 4 095 760. Между страницами 55 и 56 точное значение выросло с 3 308 до 3 442. Снимок содержит 785 нарушений без категории, 176 для Create и 48 для Performance. Раннюю остановку на одной карточке ниже порога оставляем выключенной для выдачи CurseForge без надёжной гарантии порядка. Порог сравнивается по целому `tileProjects[].downloadsCount`. После исправления парсера повторно разобраны все 674 страницы из архива. Порядок ID и точные счётчики совпали со снимком всех трёх заданий.

Зафиксированы 86 выдач порций фактов. На 83 запусках измерена фактическая модель GPT‑6 Luna Medium. Ввод составил 2 472 045 токенов, из них 813 440 кэшированных. Вывод составил 360 220 токенов. 6 890 секунд — сумма длительностей измеренных запусков, включая параллельные. Из 1 830 назначений 90 были повторами. 106 сохранённых решений по Create и 10 по Performance отражают решения о составе. Очередь фактов в снимке содержала соответственно 1 503 и 253 готовых записи.

Последний накопительный счётчик основного чата — 145 575 070 входных токенов, из них 143 661 568 кэшированных, и 195 359 выходных. В журнале есть 550 вызовов исполнения и 24 ожидания. Это счётчики всего тестового чата за несколько этапов. По ним нельзя вычислить процент лимита подписки или отнести весь объём к вызовам MCP.

## Предпроверка, Prism и запуск игры

Предпроверка 99 выбранных проектов завершилась HTTP 403 за 0,89 с. Две последующие попытки отменили через 137 м 00 с и 4 м 45 с. В снимке есть промежуточный план со статусом `export_ready: false`. В нём зафиксировано исключение Create: Escalated и оставшиеся требования по документации авторов. Из одного плана или из импорта Prism нельзя вывести, что штатная предпроверка и экспорт отработали целиком.

В Prism 11.1.1 импортировали вручную исправленный архив для Minecraft 1.21.1 и NeoForge 21.1.267. Манифест содержит 131 конкретную пару ID проекта и файла. Два JAR добавлены как вложения в `overrides/mods`. Prism запросил явное доверие для CC:Tweaked и Space War Aeronautics. Исходный ZIP в архив аудита не вложен. Сохранены его манифест, состав и контрольная сумма.

После импорта меняли файлы по журналам ограничений версий и ошибок запуска. Затронуты TFMG, Radars и JEI. Два запуска упали на отсутствующем классе интеграции KubeJS Create, которую использовал Create Vintage. KubeJS Create появился в последующем профиле. Ещё одно падение возникло в раннем окне загрузки NeoForge с `FileSystemNotFoundException`. Архив не устанавливает, связано ли это падение с Windows или с конкретным модом.

В очередном журнале ModernFix зафиксировал запуск за 63,868 с и загрузку 16 900 рецептов. Встроенный сервер мира стартовал в 15:58 и остановился в 16:00. Снимок содержит 232 активных JAR против 231 в ранее сохранённом списке. Единственное расхождение — Chunky. Журнал показывает исключение предгенерации из девяти предложенных оптимизаций. Когда и по какой команде Chunky появился на диске, снимок не устанавливает. FPS, длительные полёты и совместимость игровых функций отдельно не измерялись.

## Исправлено в 0.7.1

- **Установка и UTF‑8.** Windows-пакет настраивает локальный каталог Codex с путём к установленному `Scripts/python.exe`. Убрана зависимость от имени `python3` в конфигурации, которую ставит Windows-установщик. Локальные отчёты, HTML, сообщения и вывод дочернего Codex читаются и записываются в UTF‑8. Добавлен запуск браузера и Prism с учётом путей Windows и переносных установок. Если браузер для CDP закрыт, ошибка теперь указывает, как открыть его и продолжить существующее задание. ZIP публикуется в Windows без перезаписи и без требования жёстких ссылок.
- **Первый сбой каталога.** Плагин теперь принимает подчёркивание в slug, сохраняя проверку безопасного сегмента пути. На реальных сохранённых страницах 18, 71 и 492 найдены `shrink_`, `cat_jam` и `jeb_-wool`. После исправления порядок и точные счётчики совпали с сохранёнными записями.
- **Неразрешимый обязательный мод.** Решатель прекращает поиск, если у проекта основного состава отсутствует подходящий файл, закреплённый ID или метаданные. Для зависимостей, которые могут исчезнуть при смене версии родительского мода, перебор сохранён. В воспроизводимом локальном примере с восемью независимыми модами по три версии и девятым без файла медиана девяти замеров снизилась с 49,9 до 0,10 мс. Проверок отмены стало 18 вместо 16 410 при тех же девяти запросах к тестовому источнику. Из этого замера нельзя установить причину исторических 137 минут или оценить ускорение всей реальной сборки.
- **Объём снимков.** Новые HTML-снимки хранятся в gzip. Старые HTML читаются как раньше. На всех 2 678 исходных снимках из архива один и тот же текст занимал 664 653 709 байт в HTML и 120 559 090 байт после gzip уровня 3. Снижение — 81,9%. Сохранённые HTML и SQLite не мигрируются автоматически.

## Что улучшать дальше

1. **Предпроверка больших списков.** Статус должен показывать, на каком проекте и фазе идёт проверка, сколько уникальных файлов уже проверено, сколько времени ушло на сеть и перебор. Сохранять проверенные пары ID между попытками с проверкой свежести перед экспортом. По этим счётчикам измерить отдельно HTTP, ожидание CDP и перебор версий. Измерения нужны до увеличения параллелизма CurseForge.
2. **Воспроизводимая сборка из разных источников.** Фиксировать один план для Create, Performance и внешних модов с источником, точным файлом, хешем и причиной ручного шага. Сверять фактические моды Prism с этим планом, включая ручные исключения. Показывать отдельными строками свежие зависимости и файлы, которые придётся получить вручную. По возможности проверять версии из JAR и вложенных библиотек. Функциональная проверка выполняется запуском тестового профиля.
3. **Охват поиска до загрузки описаний.** В начале показывать размер выдачи и явные фильтры. При рассматриваемых темах Create и Performance поиск по всем категориям начал загрузку 10 000 описаний. Выбор категорий и порога заранее даёт больший эффект, чем сокращение объяснений. Если обрабатывается только часть найденных проектов, хранить остаток очереди и показывать точный охват.
4. **Стоимость анализа.** Оставить Luna для фактов и использовать компактную выдачу для основного агента. Для 90 повторов записывать тип ошибки и повторять только конкретные записи. Продолжать по ID с короткой сводкой, держать подробные планы и логи в файлах, увеличивать интервалы пустого опроса. По возможности измерять байты и токены на этап, включая кэшированные.
5. **Скорость описаний.** Create потратил 24 м 37 с на этот этап. CDP сейчас выполняет по одной навигации за раз. Сначала измерить навигацию, извлечение, запись снимка и сохранение SQLite. Затем проверить групповые записи внутри транзакции и аккуратное переиспользование браузерной вкладки. Эффект нужно подтвердить одинаковой выборкой.
